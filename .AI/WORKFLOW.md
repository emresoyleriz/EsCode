# Story-Based Development Workflow

1. Read latest reviewed baseline and Story Issue; verify prerequisites and dependencies.
2. Fetch main and establish a story branch in a separate worktree.
3. Prepare plan, affected files, tests, risk assessment and exact scopes.
4. Obtain explicit plan approval where required by policy.
5. Implement in bounded steps, preserving unsaved buffers and revision consistency.
6. Run relevant tests and security/recovery negative tests; record actual evidence.
7. Independent review + UX visual/accessibility gate where relevant.
8. Prepare proposed changes and report evidence; user controls commit/push/merge.
9. Close only verified completed items; otherwise keep Issue open with evidence and blockers.
